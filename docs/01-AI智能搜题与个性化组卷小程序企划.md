# AI 智能搜题与个性化组卷小程序企划

> 项目代号：一题学会  
> 项目形态：微信小程序  
> 核心定位：拍一道题，获得可理解的分步讲解，并自动生成同类练习完成巩固。  
> 建议首发范围：小学高年级至初中基础数学，印刷体选择题、填空题和计算题。  
> 计划团队：2 人  
> 企划版本：v1.0  
> 编制日期：2026-10-05

## 1. 项目摘要

“一题学会”是一款面向学生和家长的 AI 错题学习小程序。用户拍摄或上传不会的题目，经确认识别结果后，系统不会只给出答案，而是按照“理解题意—提示思路—分步解答—定位知识点—生成同类练习—反馈掌握情况”的路径帮助用户完成一次学习闭环。

产品与传统搜题工具的主要差异是：不依赖大规模商业题库，不把“找到答案”作为终点，而是利用多模态模型动态理解题目、生成解释及个性化练习，将一次搜题转化为一次短时学习。

在当前工期下，项目不建设完整教师端和大型组卷平台。首发版本中的“组卷”定义为：围绕当前错题生成 3～5 道同知识点、分层难度的巩固练习，并完成在线作答、判分和解析。

## 2. 项目背景与机会

学生在家庭学习中经常遇到三个问题：题目看不懂、答案解析跳步、看懂后仍不会做同类题。家长虽然愿意辅导，但可能缺少时间或已不熟悉具体知识。传统搜题产品通常依赖题库匹配，容易出现搜不到、版本不一致、解析不适合当前学生等情况。

多模态模型已经具备题目图片理解、文本与公式识别、步骤生成和同类题生成能力，使“小规模团队构建按题个性化讲解”成为可能。微信小程序无需安装，适合在家庭学习中即拍即用，也便于通过家长或同学分享传播。

## 3. 产品目标

### 3.1 首发目标

- 用户在 60 秒内完成从拍题到获得第一条有效提示。
- 识别结果可以人工修改，避免错误识别直接污染解答。
- 每道题提供分层内容：提示、思路、步骤、答案、易错点。
- 每道错题可生成一组 3～5 题的同类练习。
- 用户能够看到最近错题、知识点和简单掌握状态。
- 形成可连续演示、可真实使用、可通过审核上线的完整 MVP。

### 3.2 非目标

首发版本不实现以下内容：

- 全学科、全学段覆盖；
- 商业题库检索和题库内容爬取；
- 整张试卷批量切题；
- 复杂几何图、证明题和手写长公式的稳定识别；
- 教师、班级、学校和作业管理后台；
- 多人协同组卷；
- Word、PDF 复杂排版与打印；
- 公开题目社区、评论和排行榜；
- 支付、会员和广告系统。

## 4. 目标用户

### 4.1 核心用户

- 小学五、六年级至初中阶段学生；
- 陪伴孩子学习但不熟悉题目知识的家长；
- 希望快速整理错题并进行针对性训练的学生。

### 4.2 核心需求

| 用户 | 当前问题 | 产品价值 |
|---|---|---|
| 学生 | 解析跳步，看答案仍不懂 | 使用符合年龄的语言逐步解释 |
| 学生 | 做完一道题后不会迁移 | 自动生成同知识点练习 |
| 家长 | 无法随时辅导具体题目 | AI 提供结构化辅导参考 |
| 学生 | 错题散落，无法持续复盘 | 自动保存知识点与练习记录 |

## 5. 核心用户流程

```text
打开小程序
  ↓
拍照或从相册选择题目
  ↓
裁剪题目区域并确认识别文字
  ↓
选择“先提示”或“查看完整讲解”
  ↓
AI 生成题意、思路、步骤、答案与易错点
  ↓
生成 3～5 道同类练习
  ↓
用户在线作答并获得反馈
  ↓
保存至错题记录和知识点统计
```

## 6. 功能规划

### 6.1 P0：上线必需功能

1. **拍照识题**
   - 拍照或从相册选择；
   - 图片裁剪与压缩；
   - 图片上传及状态反馈。

2. **题目识别确认**
   - 展示识别出的题目文本；
   - 支持用户修改公式或字符；
   - 选择年级和题型，模型判断仅作默认建议。

3. **AI 分步讲解**
   - 题意复述；
   - 解题提示；
   - 分步过程；
   - 最终答案；
   - 知识点和易错点；
   - “AI 生成，仅供学习参考”显式标识。

4. **同类练习**
   - 一次生成 3～5 道题；
   - 难度分为基础、相近、提升；
   - 选择题或可自动判定的短答案题；
   - 提交后显示得分与解析。

5. **错题历史**
   - 最近记录列表；
   - 按知识点查看；
   - 删除个人记录；
   - 显示简单的“待巩固/已练习”状态。

6. **基础安全与合规**
   - 用户协议与隐私政策；
   - AI 内容标识；
   - 图片自动删除策略；
   - 内容安全检测；
   - 错误反馈入口。

### 6.2 P1：时间允许时实现

- 苏格拉底式“只给下一步提示”；
- 收藏和重新练习；
- 每日 5 题巩固卷；
- 错误原因标签；
- 连续学习天数；
- 生成学习卡片。

### 6.3 P2：赛后商业版本

- 多学科和多学段；
- 家长端周报；
- 教师组卷和班级作业；
- 可授权题库接入；
- 个性化学习路径；
- 付费套餐与学校版本。

## 7. 页面结构

| 页面 | 主要内容 |
|---|---|
| 首页 | 拍照、相册选择、最近错题入口 |
| 题目确认页 | 裁剪、OCR 结果、人工修改、年级选择 |
| AI 讲解页 | 提示、分步解答、答案、知识点、易错点 |
| 同类练习页 | 3～5 道练习、作答、提交、解析 |
| 我的错题页 | 历史记录、知识点、练习状态 |
| 设置与协议页 | 隐私、AI 标识说明、数据删除、反馈 |

## 8. 技术方案

### 8.1 推荐架构

```text
微信小程序（TypeScript）
        ↓ HTTPS
微信云函数 / 云托管 API
        ├─ 身份与限流
        ├─ 图片临时存储
        ├─ 多模态模型调用
        ├─ 输出结构校验
        ├─ 内容安全检查
        └─ 学习记录数据库
```

模型密钥只能保存在云端环境变量中，不进入小程序代码或 Git 仓库。

### 8.2 建议数据对象

- `users`：匿名用户标识、创建时间、配额；
- `questions`：识别题目、题型、知识点、模型版本；
- `solutions`：步骤、答案、易错点和校验状态；
- `practice_sets`：生成题目、难度、答案和解析；
- `attempts`：作答结果、得分和完成时间；
- `feedback`：错误类型和用户反馈。

### 8.3 模型输出约束

后端要求模型输出固定 JSON，并进行 Schema 校验：

```json
{
  "recognizedQuestion": "",
  "subject": "数学",
  "grade": "初中",
  "questionType": "填空题",
  "knowledgePoints": [],
  "hint": "",
  "solutionSteps": [],
  "finalAnswer": "",
  "commonMistakes": [],
  "similarQuestions": []
}
```

## 9. 当前技术难点

### 9.1 题目与公式识别

普通 OCR 对分数、根号、上下标、括号和手写内容容易识别错误。识别错误会导致后续推理全部失效。

**应对方案：**

- 首发限定印刷体和单题裁剪；
- 图片进入模型前进行压缩、方向纠正和裁剪；
- 必须提供识别结果确认页；
- 暂不承诺复杂几何图和整页试卷；
- 保存失败样本，针对常见错误优化提示词。

### 9.2 数学解答可靠性

大模型可能出现计算错误、跳步、题意误判或生成错误答案。

**应对方案：**

- 要求模型先求解、再独立验算；
- 对基础算术使用确定性代码二次校验；
- 将低置信度结果标记为“建议核对”；
- 提供“答案有误”反馈；
- 测试集至少覆盖 50 道目标范围题目。

### 9.3 同类题质量与可判分性

模型可能生成条件不足、答案不唯一或难度偏离的题目。

**应对方案：**

- MVP 只生成选择题和短答案题；
- 同时要求模型返回标准答案和验算过程；
- 生成后由第二次模型调用进行题目审查；
- 审查失败时自动重新生成，不直接展示。

### 9.4 公式显示

WXML 对复杂数学排版支持有限，LaTeX 渲染、换行和不同手机兼容性需要验证。

**应对方案：**

- 使用经过小程序验证的公式渲染方案；
- 首发控制公式复杂度；
- 同时保留纯文本降级展示；
- 在主流 Android、iOS 真机上测试。

### 9.5 响应时间与调用成本

图片理解、求解、验算和出题若全部串行，可能导致等待时间过长。

**应对方案：**

- 首屏先返回识别结果，再按需生成完整讲解；
- 同类题在用户点击后生成；
- 使用分阶段加载和清晰进度文案；
- 通过用户级限流、图片压缩和结果缓存控制成本。

### 9.6 合规与审核

教育服务、未成年人信息、上传图片和 AI 生成文本都涉及审核要求。生成内容应明确标识，用户上传的图片可能包含姓名、学校等个人信息。

**应对方案：**

- 在开发第一天确认主体可选的小程序服务类目及所需资质；
- MVP 不提供付费培训、真人家教或学校管理；
- 解答和练习全程标注 AI 生成；
- 图片分析完成后按策略删除；
- 不建立公开题库，不允许用户公开发布内容；
- 提供数据删除和账号数据清理入口。

## 10. 双人施工计划与预计工期

### 10.1 人员分工

**成员 A：小程序前端与产品**

- 页面结构和交互原型；
- 拍照、裁剪、上传和状态管理；
- 讲解、练习、历史页面；
- 公式显示和真机兼容；
- 视觉设计、测试及提交材料。

**成员 B：云端与 AI**

- 云开发环境、数据库和接口；
- 模型接入、提示词和 JSON Schema；
- 结果校验、重试、限流和日志；
- 内容安全、图片删除和隐私实现；
- 测试集、模型效果与成本优化。

两人共同负责范围控制、每日联调、真机测试、审核和演示。

### 10.2 MVP 工期估算

| 阶段 | 工作内容 | 双人日历工期 |
|---|---|---:|
| 需求与原型 | 范围冻结、流程、页面原型、数据结构 | 0.5～1 天 |
| 工程搭建 | 小程序、云环境、数据库、模型接口 | 1 天 |
| 识题闭环 | 上传、识别、确认、结构化返回 | 1.5～2 天 |
| 解答展示 | 提示、步骤、答案、公式、错误处理 | 1～1.5 天 |
| 同类练习 | 生成、审查、作答、判分、解析 | 1.5～2 天 |
| 历史与统计 | 错题记录、知识点、练习状态 | 0.5～1 天 |
| 合规与测试 | 协议、AI 标识、内容安全、真机测试 | 1～1.5 天 |
| 审核与材料 | 提审、修复、说明文档、演示视频 | 2～4 天缓冲 |

**结论：**两人全职施工，功能开发约 7～9 天，连同审核修复和参赛材料需要 10～12 个日历日。前提是严格限定为单学科 MVP，并在第 7 天左右提交第一版审核。

### 10.3 建议倒排节点

- 第 1 天：需求冻结、原型、类目核验、技术验证；
- 第 2～3 天：拍照识别和解题闭环；
- 第 4 天：讲解体验与公式显示；
- 第 5～6 天：同类练习和判分；
- 第 7 天：历史、协议、安全和第一版冻结；
- 第 8 天：真机回归并提交审核；
- 第 9～11 天：修复、材料和视频；
- 第 12 天：上线检查与最终提交。

## 11. 商业价值

### 11.1 用户价值

- 高频刚需：家庭学习中“不会做一道题”每天都会发生；
- 即时反馈：不需要等待老师或家长；
- 个性化：讲解和练习围绕当前错题生成；
- 低使用门槛：无需下载 App，拍照即可使用；
- 可形成复习资产：错题和知识点能够长期积累。

### 11.2 商业模式

**阶段一：免费增长**

- 每日提供有限次数免费识题；
- 通过家长群、同学分享和学习卡片传播；
- 以“同类题巩固”建立与普通搜题产品的差异。

**阶段二：个人订阅**

- 更高每日额度；
- 深度讲解和更多练习；
- 周学习报告；
- 历史错题长期保存；
- 多学科支持。

**阶段三：家庭与教师版本**

- 家庭账号和家长周报；
- 教师生成练习、布置作业；
- 班级薄弱知识点分析；
- 学校或教培机构 SaaS 授权。

### 11.3 竞争壁垒

单纯调用模型不是壁垒。长期壁垒来自：

- 高质量错题—讲解—练习—结果数据闭环；
- 针对不同年龄的讲解风格和难度控制；
- 数学题识别、验算和生成质量评估体系；
- 用户连续学习数据形成的个性化知识图谱；
- 经授权的优质内容及教师资源。

### 11.4 成本结构

- 多模态识别与文本生成 Token；
- 图片临时存储和云函数调用；
- 数据库和日志；
- 内容安全服务；
- 审核、客服及后续合规成本。

早期最重要的单位经济指标是“完成一次识题和一组练习的模型成本”。需要通过压缩图片、分阶段调用、缓存相同结果和每日配额控制毛利。

## 12. 核心指标

### 12.1 MVP 验证指标

- 题目识别后无需修改的比例；
- 从上传到首条提示的平均时间；
- AI 解答通过人工抽查的正确率；
- 用户从解答进入同类练习的转化率；
- 同类练习完成率；
- 次日再次识题的用户比例；
- 用户反馈的答案错误率。

### 12.2 比赛展示指标

- 30～50 道测试题成功率；
- 5 位以上真实用户反馈；
- 一条完整的 60～90 秒演示路径；
- 展示一次“原题做错—AI 讲解—同类题答对”的闭环。

## 13. 风险清单

| 风险 | 概率 | 影响 | 控制措施 |
|---|---:|---:|---|
| OCR/视觉识别错误 | 高 | 高 | 限定范围、人工确认、样本测试 |
| AI 答案错误 | 中高 | 高 | 双重验算、程序校验、反馈入口 |
| 同类题不可解 | 中 | 高 | 生成后审查、失败重试 |
| 模型响应过慢 | 中 | 中高 | 分阶段返回、进度提示、超时降级 |
| 审核类目或资质问题 | 中 | 高 | 首日核验类目、减少培训属性 |
| 图片包含个人信息 | 中 | 高 | 提示遮挡、临时存储、自动删除 |
| 工期失控 | 高 | 高 | 单学科、冻结 P0、停止扩展功能 |
| 调用成本过高 | 中 | 中 | 限流、缓存、模型分级调用 |

## 14. 上线验收标准

- 目标范围内 50 道测试题能够完成识别和讲解；
- 所有识别结果均可人工修正；
- 失败、超时和空结果都有可恢复提示；
- 同类练习能够作答、判分并显示解析；
- AI 内容有清晰标识；
- 图片和历史数据删除路径有效；
- 模型密钥未出现在客户端或 Git 历史中；
- Android、iOS 至少各完成一轮真机测试；
- 小程序已通过审核并可由小程序码正常进入。

## 15. 最终建议

项目具备明确需求、高频场景和长期商业化空间，但短期成败取决于范围控制。比赛版本应坚持“单题、单学科、分步讲解、3～5 道同类练习”四个边界，把准确性、响应速度和学习闭环做完整。教师平台、完整组卷和全学科应在上线验证后继续开发，而不是进入首发关键路径。
