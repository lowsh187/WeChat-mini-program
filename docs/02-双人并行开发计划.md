# PathAI 职业试岗舱：双人并行开发计划

> 时间：2026-10-07 至 2026-10-17  
> 目标：前期通过“契约 + Mock”让两人独立推进，后期集中联调、真机、审核和提交。  
> 说明：成员 A / B 的职责来源于企划；分支、交接节奏和具体拆分为**【建议安排】**。

## 1. 最终交付目标

2026-10-17 前在微信内正式上线并稳定运行，完成：

```text
基础画像 → 最多两轮动态追问 → 三个初步岗位
→ 至少一次 3～5 分钟试岗 → 固定 Rubric 行为证据
→ 推荐前后变化 → 能力差距 → 七天职业实验
```

P0 同时包含 AI 标识、隐私说明、记录删除、匿名埋点、用户反馈、超时降级及两类真机回归。至少 3 个高质量试岗稳定可用；6 个为目标，完整六岗位试岗在企划中同时属于 P1，可按风险降级。

## 2. 并行设计原则

### 2.1 责任分区

| 成员 A：产品、前端与用户测试 | 成员 B：云端、评分与 AI |
|---|---|
| 7 个页面、组件和页面状态 | 云环境、数据库和云函数 |
| 试岗内容、页面文案与显示模型 | 六维、岗位权重和评分纯函数 |
| API 适配层、Mock、加载/错误/降级 UI | 追问题选择、AI 证据抽取、JSON Schema |
| 视觉、演示流程、真机体验 | 超时、重试、降级、日志、内容安全 |
| 用户招募、访谈、参赛材料 | 埋点统计、部署和云端测试 |

### 2.2 防干扰边界

- A 只消费冻结的 ViewModel，不依赖云函数完成才开发页面；前期全部使用同结构 Mock。
- B 只按冻结契约返回数据，不改页面；使用 fixtures 和云函数测试完成独立验收。
- 共享区仅包括契约、枚举、固定配置、fixtures 和验收样本；共享区变更须双方确认。
- 页面源文件归 A，云函数源文件归 B；减少同文件编辑。
- **【建议安排】**10 月 7 日完成一次 60～90 分钟契约冻结；10 月 8～10 日只做每日 15 分钟风险同步，不做持续结对。
- 企划要求“每天一次端到端验收”。为兼顾独立开发，10 月 7～9 日用已冻结样本做可运行切片验收，10 月 10 日起做真实端到端验收。

## 3. 接口冻结包（10 月 7 日共同完成）

必须冻结：

1. 六个能力维度、六个岗位 ID、分数范围和固定公式；
2. 7 页所需数据模型，以及推荐卡、证据卡、能力差距、七天任务 ViewModel；
3. `createSession`、`selectFollowup`、`getInitialRecommendation`、`scoreTrial`、`getActionPlan`、`submitFeedback`、`trackEvent`、`deleteSession` 的请求/响应；
4. 统一错误码：参数错误、Schema 错误、AI 超时、AI 不可用、内容风险、会话过期、未知错误；
5. Mock：正常、空状态、15 秒超时、降级、非法评分、网络错误；
6. 三组稳定演示答案和预期证据/分数区间；
7. `contractVersion`、`configVersion` 及兼容规则。

验收门禁：A 能仅靠 Mock 连续走完 7 页；B 能仅靠 fixtures 跑通云函数链并返回同结构数据。

## 5. 分阶段依赖关系

### 阶段一：10 月 7 日，共同定边界

唯一强协作日：冻结范围、内容 ID、契约、Mock、验收样本和降级顺序。完成后双方可并行。

### 阶段二：10 月 8～9 日，完全独立开发

- A 的输入：契约与 Mock；输出：可用 Mock 走通的前端流程。
- B 的输入：契约与 fixtures；输出：可测试的云端流程。
- 禁止临时等待对方；缺失数据一律先用约定 Mock 或 fixture。

### 阶段三：10 月 10～11 日，按纵向切片联调

不要一次连接所有接口，依次合并：

1. 匿名会话 + 初步推荐；
2. 单个优先试岗 + 评分证据；
3. 推荐变化 + 能力差距；
4. 七天计划；
5. 其余试岗。

每个切片必须同时验证成功、超时、Schema 错误和降级四条路径。

### 阶段四：10 月 12～13 日，候选版与审核

协作重点从“开发”转为“质量门禁”：真机、隐私、删除、AI 标识、匿名埋点、生产配置、审核材料。10 月 13 日提交后冻结功能。

### 阶段五：10 月 14～17 日，验证、材料与缓冲

A 主导真实用户和材料；B 主导运行监控和严重问题处理。只有审核问题、数据不可用、流程中断或安全问题能进入热修。

## 6. 每日工作节奏

**【建议安排】**

- 09:30：15 分钟同步，只报告阻塞、契约变更和当日门禁；
- 17:30：各自提交可运行成果和证据；
- 18:00：按企划要求做一次端到端验收；10 月 7～9 日可使用 Mock/fixture；
- 18:30：更新风险、缺陷优先级和次日范围；
- 任一 P0 超过半天未打通，立即评估企划既定降级方案。

缺陷优先级：

- P0 阻塞：无法完成闭环、数据泄露、删除失效、评分无证据、生产不可用；立即处理。
- P1 严重：某设备主要路径异常、频繁超时且无降级、明显评分漂移；当天处理。
- P2 普通：视觉、文案或低频体验问题；审核后原则上不处理。

## 7. 降级触发器

| 触发时点与信号 | 立即动作 |
|---|---|
| 10-10 晚仍未稳定跑通一个真实试岗 | 追问固定为预设题库；只保留单次 AI 评分调用 |
| 10-11 中午三试岗仍不稳定 | 冻结 3 个优先试岗，不扩展到 6 个 |
| 10-11 晚行动计划生成不稳定 | 改为岗位模板 + 1 条个性化建议 |
| 10-12 真机图表问题阻塞 | 雷达图改能力条形图 |
| 10-12 仍有非核心功能未完成 | 删除历史记录、提醒与分享卡开发计划 |
| 云数据库短时异常 | 使用本地会话保存；保留核心演示闭环 |

无论如何保留：初步推荐 → 一次试岗 → AI 行为证据 → 推荐变化。

## 8. Git 与交付建议

- **【建议安排】**`main` 始终对应可提交版；`develop` 用于已通过集成验收的成果。
- A 使用 `feature/a-*`，B 使用 `feature/b-*`；短分支、小提交、合并前自测。
- 共享契约放在单独目录；契约 PR 需双方确认后合并。
- 不把密钥、真实用户完整回答、生产导出数据提交到仓库。
- 关键标签：`candidate-20261012`、`review-20261013`、`final-20261016`（名称为建议）。

## 10. 最终联合验收标准

- 两台不同系统真实手机可以完成完整流程；
- 至少 3 个岗位试岗稳定可用，每个 3～5 分钟；
- AI 结果通过固定 JSON Schema，所有评价含具体行为证据；
- 同一演示答案多次评分无明显漂移；
- 15 秒超时能返回模板化降级；
- 推荐前后变化由固定公式计算且解释清楚；
- 用户可重新试岗、删除个人记录；所有 AI 内容有显式标识；
- 匿名埋点可产出企划要求的漏斗与帮助度指标；
- 至少 20 名真实用户完成体验，反馈和活跃量无伪造；
- 介绍 PDF、AppID、小程序码、授权材料、第三方与 AI 使用说明齐全；
- 2026-10-17 前正式上线并可在微信内正常运行。
