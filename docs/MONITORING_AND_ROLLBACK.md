# 10 月 14～15 日监控、指标与回滚手册

> 本文定义统计和运维做法，不包含虚构的用户数据。所有真实数字必须来自指定云环境、明确时间窗口内的匿名导出。

## 1. 每日稳定性摘要

摘要至少包含：

- 匿名会话样本量；
- 事件数、错误事件数、错误事件占比；
- 降级事件数和降级事件占比；
- 有耗时样本的平均值、P50、P95 和最大值；
- 漏斗每一步的匿名会话数及相邻转化率；
- 完成率；
- 反馈样本量、平均帮助度及 1～5 分分布；
- 统计窗口和限制说明。

没有数据时必须显示 `insufficient_data` 和 `null`，不得写成 0、100% 或“运行正常”。

这里的错误率和降级率分母是有效匿名埋点事件数，不等同于云函数调用错误率。云函数调用错误率必须从云控制台单独读取并注明来源。漏斗按连续通过前序步骤的匿名会话计算，避免后续事件数大于前序事件时出现超过 100% 的转化率。

## 2. 建议事件目录（待成员 A 确认）

以下名称只是建议，不应在成员 A 确认页面触发点前视为冻结契约：

```text
session.created
profile.completed
recommendation.viewed
trial.started
trial.completed
plan.viewed
error.<分类>
degraded.<分类>
```

埋点不得包含题目答案、试岗回答、反馈正文、手机号、邮箱、OpenID、删除令牌或 AI 提示词。

## 3. 匿名数据导出格式

手动从同一个云环境导出 `events` 和 `feedback` 后，整理为：

```json
{
  "windowStart": "2026-10-14T00:00:00.000+08:00",
  "windowEnd": "2026-10-15T00:00:00.000+08:00",
  "funnelStages": [
    "session.created",
    "profile.completed",
    "recommendation.viewed",
    "trial.started",
    "trial.completed",
    "plan.viewed"
  ],
  "events": [],
  "feedback": []
}
```

空数组只是格式示例，不代表真实指标为零。

生成摘要：

```powershell
npm run metrics:summarize -- --input .\private\metrics-export.json --output .\private\stability-summary.json
```

`private/` 应保持在 Git 忽略范围内；提交材料中只使用经人工复核、不能定位个人的汇总数字。

## 4. 10 月 14 日监控流程（手动）

1. 确认云控制台选择的是目标环境，不混用 `cloud1` 和生产环境。
2. 记录统计窗口、部署提交、配置版本和云函数版本。
3. 查看云函数错误日志、调用次数、耗时和超时。
4. 导出匿名 `events`、`feedback`。
5. 使用本仓库脚本生成摘要。
6. 对照原始聚合结果人工复核。
7. 只有审核阻塞或严重线上问题才修改代码；不得临时修改核心权重。

## 5. 10 月 15 日稳定性复测

至少覆盖：

- 正常会话、过期会话和错误删除令牌；
- 未知题目、岗位、维度、事件和越界分数；
- AI 超时、一次重试、非法 Schema 和明确降级；
- 反馈重复提交；
- 行动计划重复生成；
- 删除后关联数据不可查询；
- 日志中没有回答正文、密钥或令牌；
- 两台真机和弱网测试（手动）。

自动复测命令：

```powershell
npm run check
```

## 6. 可回滚包清单（手动生成）

发布前保存：

- Git 提交 SHA 和只读标签；
- `contractVersion`、`configVersion`；
- 云环境 ID；
- 每个云函数的已部署版本和运行时；
- 数据库集合、权限、索引及种子版本；
- AI Provider、模型名和安全变量名称，不保存密钥值；
- 完整检查结果、真机结果和已知限制。

可以从确认过的提交生成源码归档，但归档和标签均需负责人手动执行并复核目标提交。

## 7. 回滚步骤（手动）

1. 停止继续发布并保存当前错误日志和部署信息。
2. 确认需要回滚的具体云函数，不默认全量回滚。
3. 从最近一个已验证标签建立独立临时工作区。
4. 运行 `npm run check`。
5. 仅重新部署受影响云函数到原环境。
6. 使用不含个人信息的冒烟样本验证。
7. 记录回滚时间、原因、版本及验证结果。

数据库破坏性回滚、批量删除和跨环境复制必须单独审批，不能仅凭本文自动执行。
