# AI 拍照识别与步骤指导小程序企划

> 项目代号：一步一步  
> 项目形态：微信小程序  
> 核心定位：拍下或上传看不懂的界面、通知和说明，AI 用简单语言解释，并生成可执行步骤。  
> 建议首发范围：手机截图、办事通知、软件错误提示和日常说明页面。  
> 计划团队：2 人  
> 企划版本：v1.0  
> 编制日期：2026-10-05

## 1. 项目摘要

“一步一步”是一款面向普通用户，尤其是中老年人和数字工具使用困难人群的 AI 图片理解小程序。用户上传一张手机截图、通知页面、软件提示或日常说明，系统识别其中的关键内容，以更易理解的语言回答三个问题：这是什么、我应该做什么、下一步怎么做。

产品不直接替用户操作第三方应用，也不对政府、金融、医疗等结果作权威判断。它是一层“数字信息翻译器”，把复杂页面转换成解释、重点和操作清单，帮助用户降低使用数字服务的门槛。

首发版本聚焦单张图片分析，不建设实时屏幕共享、悬浮窗、远程控制或复杂社交系统，以保证两人团队能在较短周期内完成开发、审核和上线。

## 2. 项目背景与机会

手机应用、线上办事和电子通知已经成为日常生活基础设施，但界面中的专业术语、复杂按钮、错误代码和密集信息给部分用户带来明显障碍。年轻用户也经常需要远程帮助父母判断“这个页面是什么意思”“下一步点哪里”“这条通知需要准备什么”。

传统 OCR 只能提取文字，搜索引擎则需要用户先正确描述问题。多模态模型能够同时理解文字、界面层级和上下文，使“对一张截图进行解释并转化为行动步骤”成为新的轻量产品形态。

微信是家庭沟通和公共服务的重要入口，小程序无需安装，适合作为随用随走的辅助工具，并可通过家庭成员分享快速触达目标用户。

## 3. 产品目标

### 3.1 首发目标

- 用户通过一次拍照或选图获得易懂解释；
- 自动提取图片中的关键时间、地点、材料、费用和截止日期；
- 针对界面类截图生成分步骤操作说明；
- 提供大字号、短句和清晰的视觉层级；
- 对诈骗、付款、账号、医疗等敏感场景提供风险提醒；
- 图片分析完成后按照明确策略删除；
- 形成 4～5 个页面的完整可上线 MVP。

### 3.2 非目标

首发版本不实现：

- 远程控制用户手机；
- 实时读取屏幕或其他应用内容；
- 自动点击第三方应用按钮；
- 对金融、医疗、政务结果作权威认定；
- 身份证、银行卡等证件识别与保存；
- 自动填写和提交第三方表单；
- 用户公开社区；
- 实时视频客服；
- 多张长图和复杂文档批量处理。

## 4. 目标用户与场景

### 4.1 核心用户

- 对智能手机操作不熟悉的中老年用户；
- 经常远程帮助父母处理手机问题的子女；
- 面对复杂通知、英文界面或错误提示的普通用户；
- 阅读能力或数字信息处理能力较弱的用户。

### 4.2 首发场景

| 场景 | 用户问题 | 输出结果 |
|---|---|---|
| 手机应用截图 | 不知道页面是什么、下一步点哪里 | 页面解释、按钮位置描述、操作步骤 |
| 活动或办事通知 | 信息太多，容易漏掉要求 | 时间、地点、材料、截止日期、待办 |
| 软件错误提示 | 看不懂错误代码 | 简单解释、可尝试的安全解决步骤 |
| 英文或专业界面 | 术语难理解 | 中文简化解释、关键按钮含义 |
| 疑似诈骗页面 | 不确定是否安全 | 风险信号、停止操作建议、官方核验路径 |

## 5. 核心用户流程

```text
打开小程序
  ↓
选择分析模式
  ├─ 教我怎么操作
  ├─ 帮我读懂通知
  └─ 提取成待办
  ↓
拍照或选择图片
  ↓
裁剪并确认图片不含不必要的敏感信息
  ↓
AI 识别页面类型与关键信息
  ↓
输出简单解释、重点、步骤和风险提醒
  ↓
复制结果 / 生成待办 / 保存分析记录
```

## 6. 功能规划

### 6.1 P0：上线必需功能

1. **图片输入**
   - 拍照或从相册选择；
   - 裁剪、压缩、方向处理；
   - 上传前隐私提示。

2. **三种分析模式**
   - 教我怎么操作；
   - 帮我读懂通知；
   - 提取成待办。

3. **结构化 AI 结果**
   - 图片/页面类型；
   - 一句话解释；
   - 关键内容；
   - 分步骤操作；
   - 时间、地点、材料和金额；
   - 风险提示；
   - 不确定信息说明。

4. **易读体验**
   - 默认大字号；
   - 一步一卡片；
   - 重点颜色和图标；
   - 避免专业术语；
   - 一键复制。

5. **历史记录**
   - 保存结构化结果；
   - 用户自主选择是否保存原图；
   - 删除单条或清空记录。

6. **基础安全与合规**
   - AI 内容显式标识；
   - 隐私政策和用户协议；
   - 内容安全检测；
   - 敏感场景提示；
   - 数据删除机制。

### 6.2 P1：时间允许时实现

- 朗读分析结果；
- 将日期生成小程序内部待办；
- 家庭成员分享分析卡片；
- “看不懂，再简单一点”二次解释；
- 对关键区域生成编号标注图；
- 用户反馈“解决了/没解决”。

### 6.3 P2：赛后商业版本

- 多轮追问；
- 多图片连续分析；
- 企业客服知识库；
- 适老化公共服务入口；
- 社区、银行、医院等机构定制版；
- 人工客服升级通道；
- 多语言和方言语音交互。

|---|---|
| 首页 | 三种模式、拍照、相册选择、示例 |

## 8. 技术方案

### 8.1 推荐架构

```text
微信小程序（TypeScript）
        ↓ HTTPS
微信云函数 / 云托管 API
        ├─ 匿名身份与配额
        ├─ 图片临时存储
        ├─ 多模态模型调用
        ├─ 场景分类与风险规则
        ├─ JSON 结构校验
        ├─ 内容安全检测
        └─ 结构化历史记录
```

### 8.2 建议数据对象

- `users`：用户标识、字号偏好、配额；
- `analysis_tasks`：模式、状态、耗时和模型版本；
- `analysis_results`：解释、步骤、重点、风险等级；
- `reminders`：待办内容、日期和完成状态；
- `feedback`：结果是否有用、问题类型；
- `safety_events`：敏感场景类别，不保存不必要的原始隐私信息。

### 8.3 模型输出约束

```json
{
  "sceneType": "app_screen",
  "summary": "",
  "importantItems": [],
  "actionSteps": [],
  "dates": [],
  "locations": [],
  "materials": [],
  "amounts": [],
  "riskLevel": "low",
  "riskReasons": [],
  "uncertainties": []
}
```

客户端只渲染通过 Schema 校验的数据。模型返回格式错误时，后端应重试或降级为简单文本解释。

## 9. 当前技术难点

### 9.1 界面语义理解与步骤定位

模型可能正确识别文字，但不一定准确理解按钮关系、弹窗层级和下一步操作。不同版本的应用界面也会变化。

**应对方案：**

- 不承诺像素级自动点击；
- 使用“按钮文字、颜色、所在区域”描述位置；
- 对不确定步骤明确标记；
- 结果中优先建议用户查看官方帮助；
- 建立 50～100 张典型截图测试集。

### 9.2 图片中的隐私信息

截图可能包含姓名、手机号、住址、订单、聊天内容、账号或验证码，是本项目最重要的风险之一。

**应对方案：**

- 上传前提醒裁剪和遮挡；
- 默认只处理单张裁剪区域；
- 原图设置短期生命周期并自动删除；
- 历史记录默认仅保存结构化结果；
- 明确禁止上传密码、验证码、身份证和银行卡；
- 日志中不记录完整图片 URL 和识别文本。

### 9.3 错误指导的责任风险

如果模型误解付款、医疗、政务或账号安全页面，可能给用户造成损失。

**应对方案：**

- 对付款、转账、验证码、医疗和账号安全建立关键词与视觉场景规则；
- 高风险场景不输出确定性操作命令；
- 建议暂停操作并通过官方渠道核验；
- 明确显示“AI 可能出错”；
- 不提供代操作、不采集凭证、不自动提交表单。

### 9.4 关键区域可视化标注

若希望在原图上绘制“第 1 步点击这里”，模型需要稳定输出坐标框；不同模型的坐标体系和准确率差异较大。

**应对方案：**

- MVP 使用文字描述，图片标注作为 P1；
- 若实现标注，后端统一坐标到 0～1000；
- 对框选区域进行边界校验；
- 标注不确定时不画框，避免误导。

### 9.5 长文本通知的信息抽取

通知中可能包含多个日期、条件和例外条款，简单摘要容易遗漏关键限制。

**应对方案：**

- 强制模型分别返回日期、地点、材料、费用、对象和例外；
- 在结果中保留“原文关键句”；
- 无法确认时显示不确定性；
- 提醒用户以原通知为准。

### 9.6 响应速度和弱网体验

图片上传及多模态模型调用可能耗时 5～20 秒，中老年用户容易误以为操作失败。

**应对方案：**

- 上传前压缩图片；
- 分阶段展示“上传中、识别中、整理步骤中”；
- 提供取消和重试；
- 设置超时与降级模型；
- 相同图片哈希结果可短期缓存。

### 9.7 AI 内容标识与应用审核

产品提供 AI 生成文本，需要清晰标识，并在用户协议中说明生成方式和限制。图片处理、隐私政策和服务类目也需要在提审前核验。

**应对方案：**

- 每份结果固定显示“内容由 AI 生成”；
- 复制和分享内容保留 AI 标识；
- 用户协议写明生成内容标识、数据用途和删除策略；
- 首日核验小程序主体、类目和隐私接口；
- 不在 MVP 中加入高风险专业服务。

## 10. 双人施工计划与预计工期

### 10.1 人员分工

**成员 A：小程序前端、交互与适老化体验**

- 页面原型和视觉系统；
- 拍照、相册、裁剪和上传；
- 结果卡片、步骤和待办页面；
- 大字号、无障碍与真机适配；
- 演示素材、用户测试及提交材料。

**成员 B：云端、AI 与安全**

- 云开发环境、数据库和接口；
- 多模态模型、提示词和 Schema；
- 场景分类、风险规则和内容安全；
- 临时图片生命周期、日志和限流；
- 测试集、响应速度与调用成本优化。

两人共同负责产品范围、每日联调、隐私评审、审核和演示。

### 10.2 MVP 工期估算

| 阶段 | 工作内容 | 双人日历工期 |
|---|---|---:|
| 需求与原型 | 三种模式、页面原型、风险边界 | 0.5～1 天 |
| 工程搭建 | 小程序、云环境、数据结构、模型接口 | 1 天 |
| 图片分析闭环 | 拍照、裁剪、上传、模型分析、结构化返回 | 1.5～2 天 |
| 结果与待办 | 解释、步骤、关键信息、复制、内部待办 | 1～1.5 天 |
| 历史与设置 | 记录、删除、字号、反馈 | 0.5～1 天 |
| 风险与隐私 | 敏感场景、协议、AI 标识、图片删除 | 1～1.5 天 |
| 测试和优化 | 测试集、真机、弱网、错误状态 | 1～1.5 天 |
| 审核与材料 | 提审、修复、文档、演示视频 | 2～4 天缓冲 |

**结论：**两人全职施工，功能开发约 6～8 天，连同审核修复和参赛材料需要 9～12 个日历日。相比搜题项目，本项目不需要公式渲染、数学验算和题目判分，按时交付概率更高。

### 10.3 建议倒排节点

- 第 1 天：范围、原型、类目与隐私验证；
- 第 2～3 天：图片上传和三种模式分析闭环；
- 第 4 天：结果卡片、步骤和信息抽取；
- 第 5 天：历史、待办、大字号体验；
- 第 6 天：风险规则、协议、AI 标识；
- 第 7 天：测试集、真机回归和版本冻结；
- 第 8 天：提交第一版审核；
- 第 9～11 天：修复、用户测试和材料；
- 第 12 天：上线检查与最终提交。

## 11. 商业价值

### 11.1 用户价值

- 降低数字服务使用门槛；
- 减少家庭成员远程解释的时间成本；
- 将密集通知转化为明确行动；
- 帮助用户识别常见风险信号；
- 适合低频但高价值的“遇到问题立即使用”场景。

### 11.2 商业模式

**个人免费增值**

- 每日有限次数免费分析；
- 订阅后提供更多次数、长图、多轮追问、语音朗读和更长历史；
- 家庭套餐允许多位家庭成员使用。

**机构定制**

- 社区适老化服务；
- 银行、运营商、医院的数字服务辅助；
- 政务办事指南的易读解释；
- 企业客服截图诊断；
- 公益组织数字助老项目。

**企业 API / SaaS**

- 将截图解释能力接入企业客服；
- 对产品错误截图自动分类；
- 为客服人员生成标准回复步骤；
- 建设企业私有知识库增强版本。

### 11.3 市场扩展方向

- 适老化：大字号、语音和极简步骤；
- 无障碍：为认知或阅读困难用户简化信息；
- 跨语言：解释英文或其他语言界面；
- 客服：从用户截图快速判断问题；
- 公共服务：将复杂办事指南转换为个人清单。

### 11.4 竞争壁垒

通用视觉模型本身不是壁垒。可持续壁垒包括：

- 多场景截图的高质量测试集；
- 风险场景识别和安全输出规则；
- 针对中老年用户验证过的解释方式；
- 不同应用和通知类型的场景模板；
- 机构知识库和官方操作流程接入；
- “是否解决问题”的真实反馈数据。

### 11.5 成本结构

- 多模态模型调用；
- 图片临时存储和流量；
- 云函数与数据库；
- 内容安全和风险检测；
- 隐私、安全、客服与机构合作成本。

可以通过图片压缩、低风险场景使用轻量模型、高风险场景二次判断、短期缓存和每日配额控制单位成本。

## 12. 核心指标

### 12.1 MVP 验证指标

- 分析成功率；
- 从上传到返回结果的平均时间；
- 关键信息抽取准确率；
- 用户点击“解决了”的比例；
- 结果复制或生成待办的比例；
- 次日和七日再次使用比例；
- 高风险场景误导率；
- 原图按时删除成功率。

### 12.2 比赛展示指标

- 至少 50 张不同场景截图的测试结果；
- 至少 5 位目标用户参与可用性测试；
- 展示“复杂截图—简单解释—行动步骤—生成待办”完整闭环；
- 准备一个适老化案例和一个风险识别案例；
- 形成 60～90 秒演示视频。

## 13. 风险清单

| 风险 | 概率 | 影响 | 控制措施 |
|---|---:|---:|---|
| 模型误解界面 | 中高 | 高 | 不确定性提示、文字定位、测试集 |
| 错误指导付款或账号操作 | 中 | 极高 | 高风险规则、停止操作、官方核验 |
| 上传图片泄露隐私 | 中 | 极高 | 裁剪提示、自动删除、最小化日志 |
| 响应等待过长 | 中 | 中 | 图片压缩、进度反馈、超时降级 |
| 长通知遗漏条件 | 中 | 高 | 分类抽取、保留关键原文、提醒核对 |
| 类目或审核问题 | 中 | 高 | 首日核验、协议完整、减少敏感服务 |
| 用户觉得功能可被通用模型替代 | 中 | 高 | 适老体验、结构化步骤、风险规则、待办闭环 |
| 工期扩张 | 中 | 高 | 单图、三模式、停止实时标注等 P1 功能 |

## 14. 上线验收标准

- 三种模式都能完成图片上传和分析；
- 所有结果均包含 AI 内容标识；
- 高风险样本不会输出直接转账、提供验证码等指令；
- 图片可以按策略自动删除，用户可以清除历史；
- 模型密钥未进入客户端和 Git 历史；
- 失败、超时、弱网和空结果都有明确处理；
- 大字号模式在主流尺寸设备可正常显示；
- Android、iOS 至少各完成一轮真机测试；
- 小程序已通过审核并可扫码正常使用。

## 15. 最终建议

该项目开发复杂度低于搜题小程序，社会价值和现场演示效果较强，尤其适合时间紧张的两人团队。比赛版本应突出“数字信息无障碍”和“AI 把复杂页面变成可执行步骤”，而不是包装成万能识图工具。

首发必须坚守安全边界：不代替用户操作、不处理凭证、不对高风险事项下确定结论、默认不长期保存图片。若能通过真实中老年用户测试证明步骤更容易理解，该项目在实用性、用户体验和社会价值方面会有较强竞争力。
